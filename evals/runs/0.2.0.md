with *"a full behavioural run is owed before the next minor"*. This is the next minor, and the
run has not happened. Saying it in those words is the whole point of a forward-only record: the

## Noticed, not asked

- **The suite has grown 17 → 22 scenarios across two releases without a single execution.** The
  rubric is now large enough that "run it before the next minor" is no longer a small ask, and
  that is itself a finding: an eval suite that only grows is a document, not a gate. If the next
  session cannot afford all 22, the honest move is a **stratified subset run at full N** — 1, 4,
  10, 22 — with the rest listed `not run`, rather than all 22 at N=1, which measures noise.
- **Two of this release's rules are checkable mechanically and cheaply**, before any player is
  dispatched: whether an audit autopilot exists with a member subscriber, and whether a blocked
  issue is what `status.sh` reports. Those belong in the cheap-assertion pass the README already
  argues for, and would have cost nothing today.

## Added after the first cut of this record

The release was re-cut on the same day: **v0.2.1 was published and then withdrawn at the owner's
instruction**, and its contents folded back into 0.2.0. The reason it existed is worth keeping —
0.2.0 first shipped a claim about attachment previews that had been **inferred from an HTTP
`content_type` header instead of obtained by opening the app**, and it was wrong in both
directions. No scenario in this rubric catches that class of defect, and none is proposed: the
check that finds it is the **adversarial lens**, asking of a claim *what is this actually evidence
of*. Recorded here so the next release knows it was a lens failure, not an eval gap.
